# Phase 2: Password Spraying (T1110.003)

## Attack

Password spraying attempts common passwords against many accounts to stay under lockout thresholds. Real attempts were run against genuine AD accounts via `runas` and `net use`, generating EventID 4625 (failed logon).

## Two infrastructure findings worth noting

**Windows Server 2025 anti-spray throttling**: network-based spray attempts via `netexec` from Kali consistently timed out on any multi-account or wrong-password attempt, while single correct-credential connections succeeded instantly. This was identified as Windows Server 2025's built-in network-level anti-brute-force throttling, a legitimate OS security control, not a lab misconfiguration.

**Missing audit policy**: no 4625 events were being generated by any method (network or local) until `auditpol /get /subcategory:"Logon"` revealed that Logon failure auditing had never been enabled on the DC. Every failed authentication attempt was genuinely happening, it just wasn't being logged. Fixed with:

auditpol /set /subcategory:"Logon" /success:enable /failure:enable


## Detection rule

```kql
AuthFailureDetection_CL
| where TargetUserName_s !endswith "$"
| summarize FailedAttempts = count(), DistinctUsers = dcount(TargetUserName_s), Users = make_set(TargetUserName_s) by Computer, bin(TimeGenerated, 15m)
| where DistinctUsers >= 3
```

Flags any 15-minute window where 3+ distinct accounts fail authentication on the same host. Validated against real attack-generated telemetry; pipeline (ingestion → KQL → rule → incident) additionally validated with synthetic telemetry matching the same schema, timestamped to the evaluation window, a standard detection-engineering technique for testing rule logic independent of live attack timing.
